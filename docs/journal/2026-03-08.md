## Architectural Decisions
1. **Framework Choice: Django (Python)**
   - *Rationale:* Selected for its unparalleled speed in standing up an MVP. It provides a built-in admin panel for immediate data management and a robust App-based architecture that maps naturally to building an extensible plugin system.
   - *Note:* FastAPI was heavily considered and remains an excellent modern alternative for potential future high-performance microservices, but Django fits the immediate requirement for solid persistence and MVP speed best.

## Domain Model Decisions
Created the baseline schema within `core/models.py`. Key architectural constraints implemented:
1. **User Flexibility:** Users exist independently and can join zero or multiple Communities.
2. **Resource Ownership Constraint:** A Resource must be owned by either a single User OR a single Community, but never both simultaneously (enforced via custom model validation `clean()` methods).
3. **Bookings:** Built to support basic lifecycle statuses (Pending, Approved, Rejected, Completed, Cancelled).
